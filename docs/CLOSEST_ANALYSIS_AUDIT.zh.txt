最接近分析的实质对照：论文规则、原生实现与可接入扩展
日期：2026-10-16

结论
====
R∀ 不是超越 may/must 框架表达能力的新抽象域。本次实际接入 Dat3M 的外部过滤
接口后，R∀ 加必要的 HB/CO 闭包和删域步骤，恢复了本项目在所测发布族上的全部
H/L/RF 域结果。因此不能把“它的默认实现没有推出”写成“它的框架不能推出”。

可保留的中心贡献是：P1–P3 的来源块锁定和网络传播给出所有候选的统一跨度界；
该界同时覆盖未决 CO 与多个 RF 来源，且不把原始来源身份合并。然后通过联合
端口摘要编译全部原始支持。这些具体条件与参数界不由抽象解释可靠性定理直接给出。

1. 确定比较对象，而非实现一个较弱的影子基线
=========================================
最接近的原文：Haas, Maseli, Meyer, Ponce de León，
Static Analysis of Memory Models for SMT Encodings，OOPSLA 2023，DOI 10.1145/3622855。
原文：https://hernanponcedeleon.github.io/pdfs/oopsla2023.pdf
原始制品：https://zenodo.org/records/8313104

核对点：§3.2 / Theorem 3.1 的过滤器合同；§4 的 ARel/AExec 定义与抽象过滤。
原文 §4 逐关系、逐事件对近似执行集合；关系间共同出现的信息会被丢弃。
它还保留控制流蕴含，支持导入外部程序事实，不能简化描述成“只有不带条件的集合”。
输入事实的合理扩展是该工作的公开接口，并非绕开其框架。

实测用该项目当前已构建的原生分析：Dat3M 4.5.0-alpha，提交
b81ec6c55503e824bb0ddc4ebac6c6f0a63d56d8（2026-09-24）。
https://github.com/hernanponcedeleon/Dat3M/tree/b81ec6c55503e824bb0ddc4ebac6c6f0a63d56d8
这是 2026 实现审计，不冒称重跑 2023 原始制品的性能结果。

experiments/Dat3mSupportAudit.java 调用原 NativeRelationAnalysis，
RELATION_ANALYSIS=NATIVE、ENABLE_EXTENDED_RELATION_ANALYSIS=true；不改基线源码，
不重写其传递规则，不调用 SMT 搜索。配置、输入过滤事实、输出三种关系的所有
may/must 对、事件映射、日志均保留。Java 适配器在外部目录编译。

同一程序用 C11 litmus 导出；逐线程、逐内存操作映射原事件 ID，并检查事件数、
读写种类和地址。原生分析不自动利用本实验的固定读值观测，因此必须通过
Assumption(rf, may, must) 提供同址同值来源域，不能让对方在更宽输入上比较。
experiments/fixed_ra.cat 恰表达本项目的固定 RA 公理及初始化 HB；不以完整 RC11
与受限 RA 的差别制造结果。所有内存事件必执行，地址/写值固定，无 RMW 等扩展。

2. 规则对照：缺少的是哪一步，已有框架能否容纳
==========================================
对象                  已有计算/保证                    本项目增补及边界
--------------------------------------------------------------------------
RF 单个必选边          may/must 可记录                  R∀ 不产生虚假的必选 RF
HB 关系闭包            从已知边作关系运算               跨全部可能来源证明共同 HB
不确定来源的析取       非关系近似可能丢失共同结论        D 非空且对每个来源检查前序
外部语义事实           明确支持过滤器输入                R∀ 能作为这样的过滤器接入
程序语义限制           控制流/别名等程序分析             本片段另利用 RF 单源、CO 全序
一般语义可靠性         保守近似、保语义简化              不能自动给出 P1–P3 的参数界
条件查询               可重新分析或调用 SMT             本项目图直接给任意原始假设的
                                                      全部支持；静态 may 不保证精确

最小例：a sb b；a、b 写同值；r 只可能读这两者。两个 RF 位都可真可假，但
HB(a,r) 必真。交集 RF 的闭包不能代替各执行 HB 的交集。该例说明“只取必选 RF”
不足，不证明所有抽象解释分析器不足，也不建立新的复杂度下界。

源码核对位置（上述提交）：NativeRelationAnalysis 的 Initializer.visitReadFrom、
InitialKnowledgeCloser.visitAssumption、ExtendedPropagator.visitComposition /
visitTransitiveClosure；RelationAnalysis.fromConfig。普通组合使用现有 must 边；
本次查到的原生规则未包含对读来源全集作 R∀ 的程序语义过滤。

3. 原生分析实测：恒定载荷 P(n,2)
================================
四种输入：
  values：只提供同址同值 RF may 域；
  K0：额外提供双方共享的旧核域、必选 RF、H/L；
  K0+R∀：从原生输出导出共同前序，再经 Assumption 回填至不动点；
  K0+R∀+闭包：再执行固定事件语义下的 H 传递闭包、同址写 H→L、
               CO 传递闭包、H 环 / FR-HB 来源删减，然后回填原生分析。
后两者是明确加上的外部分析步骤，不能把其结果归给未经扩展的原生默认分析。

 n   values RF may   K0 RF may   本项目 RF 域   K0 缺失的关键共同 HB
 2        22            18           18                  2/2
 3        44            34           34                  4/4
 4        76            54           50                  6/6
 8       280           174          114                 14/14
16      1072           606          242                 30/30

关键 HB 指每个“上轮第一次发布 → 对方本轮等待”。K0 输入已经包含上轮来源块，
仍没有把任一块内来源提前固定；关键 HB 全部在原生输出中缺失。
K0+R∀ 恢复全部这些关键边，但接口回填一个派生关系的 must 集并不自动完成所有
程序语义闭包。因此单独这一扩展的 H/L/D 仍不能与完整 K∀ 等同。

在 n=1,2,3,4,8,16 的全部六项中，K0+R∀+闭包 与本项目的 H、L 和 RF may 域
计数一致，缺失 H 和额外 RF 均为零；完整输出对照另由审计脚本验证。
这是一项正面的可接入结果，也是创新主张的限制：R∀ 与常规语义闭包可装入
已有过滤框架。真正需要额外证明的是随后可检查的全候选局部化与支持合同。

这些数字是分析精度审计；每次 Java 调用含 JVM 启动，未用于声称预处理速度胜出。
也没有在这里比较 Dat3M 的完整 SMT 求解能力。SAT/BDD 完整支持比较见新任务实验。

4. 论文应据此如何表述
====================
可以写：对明示的固定 RA 发布网络，在来源身份仍未决的情况下，给出可检查的
因果分隔证书和整个候选表示的统一宽度界；该表示保持任意原始假设下的完整支持。
具体的 K0 表示有 K_(n,n)，而 K∀ 表示有与轮数无关的界。原生分析对照显示缺失
的共同前序推理及其如何作为既有框架的扩展，而非用引理数量代替技术区别。

不应写：首次 may/must 同步分析；首次使用自动机/图商/支持编码；超越所有
Dat3M/Kater/CAAT/MSO 框架；所有弱内存都可常数宽度；所有编译步骤都线性；
静态过滤器能输出的事实只可能由本项目方法得到。

尚需投稿前外部核对：更广泛的来源量化相关工作与审稿人可能视为直接推广的程度。
本审计收窄并实证了主张，不构成“创新性已达到 PLDI”的证明。

5. 复现原生调用
===============
在 Linux/JDK 环境中先构建上述提交的 Dat3M，使 dartagnan/target/classes 和
dartagnan/target/libs 可用。从本项目 solver 目录执行：
  python experiments/dat3m_support_audit.py --dat3m /path/to/Dat3M \
      --out results/my_native_analysis
脚本在输出目录编译外部 Java 适配器，再调用原始类；输出目录必须是新目录。
随后执行独立集合审计（同时运行小规模语义审计）：
  python experiments/support_task_semantics.py --out results/my_semantics \
      --native-audit results/my_native_analysis
固定提交、设置、基线源码摘要与本次全部输出保存在
../results/support_task_20261016/native_analysis/metadata.json 及相邻文件。
