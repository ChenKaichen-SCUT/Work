完整支持任务与版本载荷族：定理补充
日期：2026-10-16

1. 保留同一弱同步机制的版本变体
==============================
在 PUBLICATION_CORE_THEOREM 的 P(n,m) 中，把阶段 i 的 x/y 数据写和数据读观测
由常量 1 换成 i，其他事件、标志位、程序序和查询合同完全相同，记为 Pv(n,m)。
两个线程在同轮仍写相同数据值，不能按数据值区分两位写者；标志仍只使用 0/1，
每轮 m 次发布之间插有第二个数据写，早/晚来源仍有不同同步效果。
这可解释为带版本标记的共享状态交换记录。它是可执行的研究协议内核，非工业日志。

新增的观测信息确实缩小跨轮数据 RF：Pv 的数据读只可能来自两个同轮写。
所以 Pv 的速度不能冒充恒定载荷 P 上的算法加速。后者继续作为重复数据值的
困难控制组。有限 C 实验使用 int 常量，已测规模无溢出；数学族允许 O(log n)
位版本值，不声称这一变体同时具有固定有限的数据值域。

主定理 P1–P3 不限制数据值必须反复相同，所以 Pv 直接满足同一来源块锁定和
网络传播证明：d=1，G=1，b=2(m+4)，a=4。二进制候选组的证明界仍为
k≤16m+68。K0 的每个数据读域为同轮两个来源，始终非单例；没有新增跨线程
必选 RF，因此 K0 的 x 写比较仍含 K_(n,n)。这个差距未因版本值消失。

至少 4^n*m^(2(n-1)) 个合法原始赋值的构造仍成立：数据读选本线程本轮写，
标志独立选上轮任意发布，x/y 的 CO 按轮拼接且同轮方向任选。原来的 sb/CO 环
仍提供非 SC 赋值。P(2,2) 的 d/e/l/q 诊断和显式倒置 CO 见证也原样适用。
因此“数据值更明确”并不意味着同步来源或 CO 已固定，也不把任务变为 SC。

进一步强化：整个固定观测在 SC 下不可达，而不只是某些 RF/CO 赋值非 SC。
主定理的来源块锁定说明：任意合法补全中，两线程第一轮 wait 均读初始化。
若存在 SC 总序，则 A 的第一轮 fa=1 发布 sb-before A 的 fb=0 等待；该等待
读取初始化要求它先于 B 的第一轮 fb=1 发布；后者又 sb-before B 的 fa=0
等待；此等待须先于 A 的第一轮 fa=1 发布，构成严格次序环。故所有 n>=1、
m>=2 的 P 和 Pv 观测均非 SC 可达。重复出现的后轮 0 值不能解开此环，因为
n 次交替读值的有序来源链已迫使第一读选择初始化。RA 可达性由上面的构造给出。
这进一步说明该任务确实需要弱内存语义；不是把 SC 可达结果换一个关系表示。
独立的事件全序 SAT 编码对两种载荷 n=1..4 全部得到 UNSAT；GenMC 对 Pv(2,2)
得到 RC11 可达、SC 不可达。Pv(4,2) 的 GenMC 60 秒超时保留为 UNKNOWN。

2. 原子化读来源组
================
对识别后非单例的可靠域 D(r)={w1,...,wh}，用 h 路组代替 h 个二选一 RF 位组。
选择 wj 时，标签同时写 RF(wj,r)=1 和其余 h-1 位=0；关系增加真实 r/R 两向
生成边，读来源计数增加一次。被识别删除的原始 RF 位仍在根标签取假，单例仍
在根标签取真。该选项不合并写事件、不删掉可查询的原始变量。

等价性：每个合法完整赋值恰选 D(r) 中一个来源，唯一对应一个组分支；反向亦然。
所有完整选择生成同一组真实 sb/RF/CO 边。禁止游走检查与边加入顺序无关，且
任何合法完整图的前缀都不会已有禁止游走，因此改变组顺序不丢合法赋值。
每个原始变量仍恰好被一个标签组拥有，端口后缀等价与支持 CNF 合同直接适用。
任意正/负 RF/CO 假设、冲突和撤销均包含在合同内。

不能继续不加说明地沿用二元边组的 k：一个来源组包含读和全部来源，跨度可达
2δ。保守取 kA=(2δ+1)b+a，h≤kA，S_A=2^(33kA²+kA)，表示大小可粗界为
O(|X|+kA²*N*S_A)，再加原识别成本。界依然独立于轮数，但常数可能更大。
其中 RF 标签计费不能省略：一个 h 路组有 h 个长度 h 的标签，贡献 h²；
全部读的标签总量至多 N*kA²，未决 CO 组仅 O(kA*N)。按状态数 S_A 复制后
得到上述表示界。超组按最大端点排序时，仍活跃的非初始化事件至多落后当前
阶段 2δ，故 kA 的窗口界适用于实际分组，而不只是每个来源单独的边跨度。
这只是完整单源选择的分组优化，不将 one-hot/MDD 分组的通用思想称为新定理。

后处理 dag_reduce 使用标准的逐层后向同标签后缀商并删除无接受后缀的状态。
同层状态的签名为 {(标签, 后继等价类)}。逐层归纳保持完整接受标签语言，故
保持全部原始支持。源码是原有 minimize_suffixes 思路的逐层低临时存储实现。
它只缩减已经构造的图；原始状态数量、构造峰值和失败预算仍必须单独报告。

可选 C++ 扩展逐步实现相同位集代数；它不改变摘要等价关系或搜索策略。
适用的产品接口至多 128 位，超过后自动使用 Python 版本，不截断接口。
原生与 Python 构造的状态/尝试/各层数量须一致；运行统计记录实际启用的步骤数。
因此状态减少、后处理缩图和底层执行速度分别作为独立因素报告。

3. 一个实际消费全部支持的任务
============================
trace_diagnosis 接受固定值执行片段和不完整的来源/写序日志。每个已记录字段是
一个 RF 来源身份或 CO 方向。客户端提供：
  (a) 对一致日志，列出每个读的全部仍可行来源与所有 CO 对的可行方向；
  (b) 对冲突日志，给出删除意义下极小的冲突字段集（不称最小基数）；
  (c) 列出所有只修改一个记录字段即可恢复一致的替换值。
没有输入的字段保持自由。修复选项分别可行，不宣称它们可以任意同时组合。

为何完整支持在此有明确用途：若撤销第 j 个 RF 字段后剩余日志一致，一次查询
即给出该读全部有支持的来源，除去原值后就是全部单字段替换。若剩余日志仍冲突，
改该字段的任何值都不能修复。CO 字段的两个方向同理。普通一次 SAT 只给一个
可行模型，不能把该模型中没出现的来源排除；比较用的 SAT 会完整搜索所有支持。

修复完备性证明：任何只改字段 j 的合法修复，都满足撤销 j 后的其余日志，
所以其替换值必在该次完整支持集中；每个返回的支持都有一个满足余日志的完整
见证，加上该替换值即为合法修复。遍历所有字段因此既不漏修复，也不报虚假修复。
极小冲突通过逐项删除且保持 UNSAT 得到，最多逐字段一次；它与最小基数不同。

实验日志由发布协议的早/晚来源与一次 CO 观测构成，客户端自身生成删字段查询，
不再把随机假设前缀当作完整任务。这些是受控的生成日志，不能称真实部署采集。
它们同时包含可行来源歧义、强制次序、冲突与可行修复；全部方法返回相同结构结果。
通用 CLI 可对独立固定 RA JSON 和用户提供的部分日志运行，不依赖协议生成器。
