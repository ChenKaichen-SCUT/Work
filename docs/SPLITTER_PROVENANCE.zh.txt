2. 实现、抽取和修改的精确边界

examples/splitter_grid.c 是我们据上述规范写的 C11 转录，不是上游原始 C 文件。
共享操作保留为四个命名点：
  wx：写本进程编号到 X；
  ry：检查门 Y，若已关闭就 right；
  wy：未关闭时将 Y 置 true；
  rx：检查 X 是否仍为自己，决定 stop 或 down。
网格 right 增列号，down 增行号，stop 结束；到原 Figure 4 的三角边界时直接
返回名字，不再产生该边界格点的共享访问。0 表示 X 的空值，进程编号用 1..p。

原规范使用原子寄存器/交错执行。我们做的明确内存序修改是：每个共享写采用
release，每个共享读采用 acquire，地址和操作顺序不变。定义 SPLITTER_SC 时
相同 C 代码改用 seq_cst，作为规范的 SC 参考。RA 版本不是原论文保证正确的
实现，重复 stop 是此移植的缺陷。没有查到本次相同移植缺陷的独立上游报告，
因此绝不把它称为某个实际库已经报告过的 bug。

代码经过 GCC 的 C11 双模式语法检查；语义证据来自独立 RA/SC 有限模型核查，
不是在某种硬件上跑到了弱行为，也不是全程序外部模型检查器的认证结果。

wmcheck/ra_splitter.py 的 extract_grid 接受每线程访问路径：
  (batch,row,col,outcome,observed_x)。
right 保留 wx,ry=1；stop 保留 wx,ry=0,wy,rx=本编号；down 保留相同四个
事件且 rx=日志中的另一编号。所有原始 RF/CO 身份保留，未指定谁读谁、写序
如何。probe 只允许作为线程日志最后一个访问：保留 wx,ry=0,wy,rx=?，最后
一次读取已发生但值没有记录；没有依赖这个未知值的后续事件。

抽取检查了路径分支、进入网格的位置、格点边界和 fresh-batch 边界。对已访问
格点不删除任何共享步骤；局部变量计算不产生共享事件。未访问格点的寄存器
及初始化不影响被保留变量的投影，可以省去。C 函数的原子类型/内存序和动态
循环不是由通用 C 前端自动解析的；这是手工说明映射、程序化生成并检查路径
的抽取器，不能宣传任意 C 程序自动抽取。

有限已确定路径仍是当前模型限制：没有验证所有动态分支、任意线程数、所有
非终止行为。后续跨对象分支值必须保留，不能用 rx=? 继续挑选有利路径。

3. 三线程的真实多来源、未决 CO 和弱行为

在根 splitter 处，A/B 都执行 wx; ry=0; wy; rx=?，C 执行 wx; ry=1 后结束
该日志前缀。寄存器 X 的写用于竞争名字，Y 的写用于关门；没有为测试加入
额外写。C 的 ry=1 可来自 A.wy 或 B.wy，两者均由独立合法见证支持。
CO(A.wy,B.wy) 两个方向均有支持；甚至在 A、B 都读自己的 X、均决定 stop
时，两种 RF 来源 × 两种 Y 写序的四种组合也都有合法支持。

这正是 RA 移植的不足：A、B 的 ry 都读到初始 false，不建立它们之间的
同步；各自 rx 可读自己刚写的编号。C 的 acquire 读取又确实从某个 release
关门写同步，并非完全没有同步的例子。

SC 下不可能同时 stop。以两个 X 写的全序为例，若 A.wx 在 B.wx 前，而
A.rx 仍读 A.wx，则 A.rx 必须在 B.wx 前；结合程序序有 A.wy 在 B.ry 前。
但 B.ry=0 又必须在任何 Y=true 写前，矛盾。反向 X 序对称。因此这不是
“规范原本允许重复名字”，也不需要额外假设物理时间。

根前缀穷举得到 88 个 RA 原始赋值、40 个 SC 原始赋值；其中双 stop 子集有
24 个 RA 赋值、0 个 SC 赋值。24 不是全部 RA/SC 差异数量（88-40=48）。

4. 完整支持的具体任务

任务是分析一段缺失最后读值的重命名日志：列出全部可能来源、检查是否可能
发出重复名字、定位不一致的补录日志，并给出全部单字段修复。

  观测/补录                             完整支持结果
  根日志                               可行；C 的门读取仍有 A/B 两个来源
  A.rx←A.wx 且 B.rx←B.wx                RA 可行，SC 不可行（重复名字）
  A.rx←B.wx                            必须 CO(A.wx,B.wx)
  B.rx←A.wx                            必须相反的 X 写序
  A.rx←B.wx 且 B.rx←A.wx                不可行；这两个补录是极小冲突
  A.rx←B.wx 且 CO(B.wx,A.wx)            不可行

在极小冲突中，删去 A 的补录后，A 可改读自己或 C 的 X 写；删去 B 的补录后，
B 可改读自己或 C 的 X 写。两类修复均保存为原始 RF 位，C 的关门来源补录
不属于该冲突。全部单字段替换来自支持查询，而非只找一个可行解释。
结果及带原始事件名的见证见 audit.json、root_probe.witnesses.json；729 个
选定六变量的三态部分赋值全部核对了所有 21 个原始位的支持和支持 CNF 的 UP。
这不是 3^21 个查询已穷尽。另用不调用识别核/编译器的 SAT 编码核对 14 个场景，
其中含上述双 stop 下 RF×CO 的四种组合，并逐一保存、重验完整见证。

5. 实例族及旧前提对照

单网格族逐层让一个线程 stop、一个 right 后在旁边的格点 stop，其余 down；
每一层的右行者都会读到多个真实关门写中的一个。这条路径在 SC 规范下也
可实现；另外提供三线程根格点重复 stop 的缺陷路径。

  旧前提                  是否自然满足/失败原因
  P1 独占标志重复发布      失败；X/Y 多写者，Y 单次 false→true，无交替块
  P2 完整交替观测          失败；路由按分支前进，没访问的格点没有观测
  P3 有界事件密度          每格点至多 4p 个事件，自然成立
  P3 跨轮写覆盖            一次性对象无需这种复用窗口；不把它宣称为新同步保证
  固定全局初始化数 a       随对象数增长；新界使用每对象 s=2
  无 RMW/fence             自然成立，来源算法本来只用读写
  固定有限事件             由日志路径抽取施加，是分析范围，不是完整程序的属性
  多来源 RF                Y=true 的多个真实写者，以及 probe 的未知 X 值
  未决 CO                  协议本身的 X/Y 竞争写；独立合法见证确认

规模增长分两轴报告：增加 p 改变同一网格的竞争和路由结构；增加 batch 则各次
使用全新网格，是我们显式声明的批处理工作负载。后者用来检验总事件数增长
时定理的参数，不是原论文 Figure 5 的长生命周期/存储复用协议。

6. 这次推广解决什么、没有解决什么

OBJECT_LOCALIZATION_THEOREM.zh.txt 证明对象 DAG 上的精确支持分解和 k<=4p+2，
无需旧 P2 的计数、无需来源块锁定，也无需无意义竞争写。它实质提供了第二种
协议结构和一项对原编译器有效的语义优化。

但“有经典正式来源”不等于“已证明现代生产程序经常满足”。实际重要性仍需
由更接近当前软件的案例支撑。新定理不能用于任意共享地址复用，当前的 C11
移植是明确的缺陷变体；这些限制必须在论文正文和图表说明中保留。
