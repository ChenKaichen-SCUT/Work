服务器退役前备份与后续实验恢复（2026-10-17）
==========================================

一、最短恢复路径

本仓库根目录就是可继续开发的最新项目。论文 PDF 在
artifacts/FM_Chinese_Manuscript.pdf；可编辑源码在 fm_chinese_paper/，
另有 artifacts/FM_Chinese_Source.zip。实验数据、失败记录和理论文档均已保留。
下载 GitHub 的 main 分支 ZIP 并解压，或：

  git clone https://github.com/ChenKaichen-SCUT/Work.git
  cd Work

Linux（Ubuntu 22.04 / Python 3.10 是原测量环境）：

  sudo apt-get update
  sudo apt-get install -y python3-venv python3-dev build-essential
  bash scripts/setup_reproduction.sh
  .venv/bin/python experiments/fm_reproduce.py --out replay-full --full

完整核查从源码编译 C++ 扩展、执行全部单元测试、结构审计、32轮独立核对和
6个环族配置。推荐至少8 GiB可用内存；不需要原服务器、其 IP 或登录凭据。
输出目录必须是新目录。只跑快速核查可去掉 --full；Windows：

  python -m venv .venv
  .venv\Scripts\python.exe -m pip install -r requirements-fm.txt
  .venv\Scripts\python.exe experiments/fm_reproduce.py --out replay-quick

最小环境不安装 CUDD，因此历史 CUDD 测试有1项跳过；这不等于验证了 BDD。
原始完整环境包版本另存 archives/server-20261017/requirements-runtime.lock。
如需历史 BDD 比较，在 Linux 的独立虚拟环境安装该 lock；绘图另安装
requirements-plots.txt。不要把新的计时覆盖到 results/ 中的冻结测量。

四、第三方基线恢复

精确拉取三个基线源码（不要使用自动跟踪最新分支的旧 bootstrap.sh）：

  python scripts/fetch_pinned_baselines.py --out ../wm-baselines

Dat3M: b81ec6c55503e824bb0ddc4ebac6c6f0a63d56d8，Java17、Maven3.6.3。
在该源码目录执行（将 /path/to/Work 替换成实际仓库绝对路径）：

  mvn -B -s /path/to/Work/scripts/maven-settings.xml -pl dartagnan -am package -DskipTests

然后回到本仓库根目录：

  .venv/bin/python experiments/dat3m_support_audit.py \
      --dat3m ../wm-baselines/Dat3M --out replay-native-analysis

  cmake -S ../wm-baselines/genmc -B ../wm-baselines/genmc/build -G Ninja \
      -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++-14 \
      -DCMAKE_C_COMPILER=gcc-14 -DCMAKE_PREFIX_PATH=/usr/lib/llvm-19/cmake
  cmake --build ../wm-baselines/genmc/build -j3
